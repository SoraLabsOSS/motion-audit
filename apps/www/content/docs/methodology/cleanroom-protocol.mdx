# Clean-Room Measurement and Provenance Protocol

## Purpose

Motion Audit is implemented from public browser standards, public Chromium/CDP
interfaces, and independently designed calibration targets. The ignored
`extracted/` directory is not an implementation specification, test oracle, or
source of constants.

This protocol separates:

1. **Public facts:** behavior documented by a standard or browser interface.
2. **Observable measurements:** values collected from a running browser.
3. **Project calibration:** tunable scoring choices owned by SoraLabs.

Only the first two categories may justify a measurement implementation. The
third must be labeled as calibration and validated with independent fixtures.

## Permitted Public Inputs

| Input | Permitted use | Boundary |
| --- | --- | --- |
| W3C Web Animations API | Read `Document.getAnimations()`, keyframes, and timing | Describes animation state; it does not prove compositor execution |
| W3C Long Animation Frames API | Observe `long-animation-frame` entries and script/render timing | Availability varies by browser version |
| CDP LayerTree | Observe layer changes and request compositing reasons | CDP output is browser-specific telemetry |
| CDP Performance/Tracing | Collect timing and rendering events | Dropped frames require interpretation of trace/timing data |
| CSS/graphics definitions | Derive CSS-pixel, DPR, and raw RGBA estimates | Raw estimates are not driver VRAM measurements |
| Public rendering guidance | Identify forced layout patterns and mitigation | Guidance does not provide numeric score weights |

## Independent Derivations

These equations are implementation primitives, not copied scoring rules:

### Raw texture estimate

For a CSS surface of width \(W\), height \(H\), and density \(d\):

$$
M_{\mathrm{raw}} = W \times H \times 4 \times d^2
$$

The result estimates an uncompressed RGBA8888 surface. Alignment, tiling,
compression, swap chains, and driver allocation are outside this equation.

### Percentile

For sorted values from x0 through x(n-1), linear interpolation at percentile
\(p\) uses:

$$
i = p(n-1), \quad
P_p = (1-(i-\lfloor i\rfloor))x_{\lfloor i\rfloor}
     +(i-\lfloor i\rfloor)x_{\lceil i\rceil}
$$

The percentile implementation must define its interpolation and keep that
choice stable across releases.

### Consecutive-frame run

Given a set of observed frame indices, begin a run only where \(f-1\) is
absent, then count \(f+1, f+2, \ldots\). This is a deterministic \(O(N)\)
hash-set calculation for the longest observed run; it is not a claim about
frame duration.

## Calibration Rules

Calibration values such as pillar weights, penalty points, memory bands,
duration floors, and tier boundaries are project parameters. Each parameter
must have:

- a named constant or table in `src/`;
- an explanation of its operational intent;
- boundary and empty-input tests;
- a statement that it is not a universal browser or hardware constant.

Synthetic fixtures may verify deterministic score behavior. They must not be
described as browser ground truth or user-perceived performance evidence.

Real-site benchmarks must report raw telemetry beside the operational score:
browser/version, viewport, DPR, run count, warm-up policy, frame timings,
LoAF/long-task observations, layer telemetry, and modeled memory. Scores are
comparative indicators within that controlled environment.

## Prohibited Inputs

- Copying or translating code, variable names, control flow, thresholds, or
  undocumented heuristics from a third-party implementation.
- Treating a third-party output as a ground-truth oracle for calibration.
- Presenting a theoretical tile or texture estimate as physical GPU allocation.
- Presenting a tier as an industry, W3C, Chromium, Lighthouse, or Core Web
  Vitals certification.
